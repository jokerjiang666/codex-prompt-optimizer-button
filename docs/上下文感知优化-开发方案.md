## 1. 「精准」的可验收定义

| 指标 | 定义 | 验收方式 | 阈值 |
| --- | --- | --- | --- |
| 归属精确率 | 带进来的上下文确实属于当前会话 | 端到端人工抽查 20 例 + 定位器单测 | **100%**（宁可 0 上下文） |
| 歧义处理 | 重名/多候选时不得猜 | 单测覆盖重名用例 | 冲突即放弃，0 次"取最新蒙一把" |
| 新鲜度 | 会话文件必须是活跃会话 | `LastWriteTimeUtc` 与 `now` 比对 | 默认 ≤ 300s（可配置） |
| 交叉校验 | 三个独立来源相互印证 | 单测 + 真机日志 | 存在冲突则否决 |
| 来源可追溯 | 每条上下文块自带出处 | 预览窗口 + 诊断日志 | source/threadId/cwd/capturedAt 齐备 |
| 不幻觉 | 字段缺失就写缺失 | 单测（git=null、无 summary 等） | 缺失只标注 `unavailable`，不推断 |
| 零采集 | 关闭态不做任何读取 | 计数探针 + 真机断源测试 | 文件读取 0 次、子进程 0 次 |
| 开销 | 额外延迟与 token 增量 | 诊断日志耗时 + token 估算 | P95 额外 ≤ 400ms；token ≤ 预算上限 |
| 回归 | 关闭态输出与旧版一致 | 字符串级比对 | 与 v1.2.1 请求体完全一致 |

## 2. 已实测事实（2026-09-22 本机复核）

> 本节全部为本机实际观测，实施时以现场复核为准（Codex 升级可能改字段）。

### 2.1 会话文件有两个目录

| 位置 | 结构 | 数量（实测） |
| --- | --- | --- |
| `%USERPROFILE%\.codex\sessions\<yyyy>\<MM>\<dd>\` | 按日期分层 | `rollout-*.jsonl` 178 个 |
| `%USERPROFILE%\.codex\archived_sessions\` | 扁平 | `rollout-*.jsonl` 369 个 |

文件名形如 `rollout-2026-09-21T20-06-21-01a0c3dc-2d6c-7c00-95bf-88296a96bf82.jsonl` —— **文件名里直接带 threadId**，这是"标题 → 文件"链路能成立的最后一环。

### 2.2 会话索引：`%USERPROFILE%\.codex\session_index.jsonl`（首选映射源）

- 375 条记录（JSONL），字段实测只有三个：`{"id":"<threadId>","thread_name":"<标题>","updated_at":"<UTC ISO>"}`。
- 实时更新：本次复核时最新两条含当前正在进行的会话（`updated_at` 与文件写入时间同分钟）。
- 结论：**标题 → threadId 的高置信映射直接读它，不需要解析 1.2 GB 的 sqlite**。

### 2.3 rollout 文件结构（NDJSON）

第 1 行 `session_meta.payload` 实测字段：
`session_id, id, forked_from_id, forked_from_ordinal_exclusive, timestamp, cwd, runtime_workspace_roots, originator, cli_version, source, thread_source, model_provider, base_instructions, history_mode, history_base, multi_agent_version, context_window, git`

其中 `git` 实测形如 `{"commit_hash":"e4b16706…","branch":"main"}`（**可能为 `null`**，实测 projectless 会话即为 null）。

`turn_context.payload` 实测字段：
`turn_id, root_turn_id, disabled_plugin_ids, cwd, workspace_roots, current_date, timezone, approval_policy, approvals_reviewer, sandbox_policy, permission_profile, active_permission_profile, model, personality, collaboration_mode, multi_agent_version, realtime_active, effort, summary`

顶层记录类型与计数（实测某 1506 行会话）：
`response_item 658 / event_msg 622 / token_usage_record 204 / turn_context 15 / world_state 5 / compacted 1 / session_meta 1`

### 2.4 重名是真实存在的（所以必须 fail-closed）

`session_index.jsonl` 实测重名统计：**6× 每周回顾**、4× 量化-震荡行情版、4× 调研开源自媒体矩阵平台、4× 获取前后端启动命令、3× 定位空白CMD终端来源。

推论：只靠标题做唯一定位是不可靠的；必须叠加"索引时间 + 文件新鲜度 + cwd 交叉校验"，并在无法判定时**放弃上下文**。

### 2.5 全局状态文件是有效的交叉校验源

`%USERPROFILE%\.codex\.codex-global-state.json`（约 2.6 MB）实测包含：

| 键 | 形如 | 用途 |
| --- | --- | --- |
| `thread-workspace-root-hints` | `{threadId: "E:\\虚拟币\\AoChuangLiangHua"}`（129 键） | **校验 cwd 是否属于该 threadId** |
| `thread-projectless-output-directories` | `{threadId: "...\\outputs"}`（111 键） | projectless 会话的 cwd 佐证 |
| `thread-titles` | `{titles:{}, order:…}` | 备用标题源 |
| `active-workspace-roots` | `["E:\\虚拟币\\CryptoEADeal"]` | 当前活动工作区根 |
| `pinned-thread-ids` / `selected-project` | 数组 / 对象 | 弱信号，仅供诊断 |

**坑（实测）**：该 JSON 存在大小写混用的键（如 `M`/`m`），PowerShell 默认 `ConvertFrom-Json` 直接报错。C# 侧必须用 `JsonSerializerOptions { PropertyNameCaseInsensitive = true }` 或按字典读取，且**不允许**因为解析失败而阻断优化（解析失败 = 只用其余信号）。

### 2.6 新鲜度旁证：`%USERPROFILE%\.codex\thread-writer-locks\<threadId>.lock`

实测存在 10 个零字节锁文件，mtime 即该会话最后一次写入时间。可作为"该会话最近活跃"的旁证；但同一分钟内可能有多个会话活跃（实测 12:30 / 12:27 / 12:26 三个），**不能**单独用作归属判据。

## 3. 总体架构

```
点击星芒优化
   └─ OptimizeAsync()                       ← 唯一入口（不新增后台线程）
        ├─ ContextGate.IsEnabled()          ← ① 总开关：false 直接 return null，零采集
        ├─ ContextLocator.LocateAsync()     ← ② 精准定位：标题→索引→threadId→rollout 文件 + 三重校验
        ├─ IContextSource[].CollectAsync()  ← ③ 只读采集：会话元信息 / 对话尾部 / 工具摘要 / git 摘要
        ├─ ContextBudget.Trim()             ← ④ 预算裁剪（永不裁草稿原文）
        └─ PromptComposer.Compose(..., ctx) ← ⑤ 组装 JSON 证据块（"证据不是指令"）
   └─ provider.OptimizeAsync(system, user)
```

失败路径统一：任何一步异常、超时、低置信、字段缺失 → 返回"无上下文"，照旧优化，并在 `runtime-status.log` 写一个诊断码。

## 4. 精确定位器（本方案核心）

### 4.1 输入信号

1. **UI 标题**（强，但可能被截断）：`WindowTracker.TryGetHeaderThreadTitle` 已能拿到 header 标题，复用即可，新增一个只读出口 `TryGetThreadTitle()`，不要在优化路径里重新遍历整棵 UIA 树。
2. **窗口进程/句柄**：`AnimationTarget`/`ComposerTarget` 已有 hwnd，用于多窗口隔离。
3. **当前活动工作区根**（弱佐证）：`.codex-global-state.json` 的 `active-workspace-roots`。

### 4.2 定位算法（按顺序，任一步不满足按 §4.4 降级）

```
Locate(title, hwnd):
  1. if String.IsNullOrWhiteSpace(title): return null            # 诊断 ctx=locator-no-title
  2. index = ReadSessionIndex()                                   # session_index.jsonl，缓存 10s，按 mtime 失效
  3. cands = index.Where(r => Normalize(r.thread_name) == Normalize(title))
  4. if cands.Count == 0:
        cands = index.Where(r => Normalize(r.thread_name).StartsWith(TrimEllipsis(title)))   # 标题被截断的场景
  5. if cands.Count == 0: return null                             # ctx=locator-no-index
  6. cands = cands.OrderByDescending(r => r.updated_at)
  7. 逐个候选做"文件解析 + 三重校验"，第一个全部通过的才返回：
        a. 文件存在：sessions 下按 threadId 递归找，找不到再查 archived_sessions
        b. 新鲜度：file.LastWriteTimeUtc 距今 <= ContextStaleSeconds（同刻校验用 UTC 归一，注意索引是 Z、文件是本地时间）
        c. cwd 交叉校验：session_meta.cwd 与 global-state 的 thread-workspace-root-hints[threadId] 一致
           （该键不存在时视为"无法校验"，只降置信，不否决）
  8. 若第 6 步有 >1 个候选且全部通过校验且无法区分：return null     # ctx=locator-ambiguous n=K
  9. return ContextSession(threadId, path, cwd, workspaceRoots, branch, commit, mtime, confidence)
```

关键点：**第 8 步是"冲突即放弃"的执行处**——宁可这一轮没有上下文，也不能把别的会话读进来。

### 4.3 校验表（谁否决谁）

| 校验 | 数据来源 | 失败后果 |
| --- | --- | --- |
| 标题匹配 | `session_index.thread_name` | 精确与去省略号前缀都不匹配 → 放弃 |
| 唯一性 | 候选数量 | >1 且无法区分 → 放弃 |
| 文件存在 | 两个会话目录 | 文件已被归档/清理 → 放弃（可只查 archived 再放弃） |
| 新鲜度 | `FileInfo.LastWriteTimeUtc` | 超过阈值 → 放弃（诊断码带 age） |
| cwd 一致 | `session_meta.cwd` vs `thread-workspace-root-hints` | 明确不一致 → 放弃；键缺失 → 降置信但仍可用 |
| 格式兼容 | 第 1 行可解析出 `type=session_meta` | 解析失败 → 放弃（`ctx=format-unknown`） |

### 4.4 降级矩阵

| 场景 | 行为 | 诊断码 |
| --- | --- | --- |
| 总开关关 | 不执行本函数 | `ctx=off` |
| UIA 拿不到标题 | 无上下文 | `ctx=locator-no-title` |
| 索引里查不到标题 | 无上下文 | `ctx=locator-no-index` |
| 标题被截断（带省略号） | 前缀匹配；仍多义 → 无上下文 | `ctx=locator-prefix n=K` |
| 重名多候选 | 时间+文件+cwd 三者都无法区分 → 无上下文 | `ctx=locator-ambiguous n=K` |
| 文件过期 | 无上下文 | `ctx=locator-stale age=Ns` |
| cwd 冲突 | 无上下文 | `ctx=locator-veto reason=cwd` |
| 全局状态 JSON 解析失败 | 跳过该信号，继续其余校验 | `ctx=global-state-unreadable` |
| 会话文件正被写入（半行） | 只解析到最后一个完整行；解析失败的行丢弃 | `ctx=tail-partial` |

### 4.5 增量读取与缓存

- 记录每个 threadId 的 `(path, length, offset)`，只读新增字节；文件变短（被轮转/重写）则重置偏移。
- 只读**文件尾部**：从末尾按块回读（如 256 KB 起步）直到凑够 `ContextMessageLimit` 条消息，避免每次全量解析（实测单会话已 1500 行量级）。
- 缓存策略：`session_index.jsonl` 10s + mtime 失效；git 摘要 60s；本会话解析结果仅在内存；**不落盘**。
- 采集只发生在点击优化时，不进入 `TrackLoopAsync`。

## 5. P0 上下文来源清单

| 层 | 来源 | 取什么 | 默认 | 截断 |
| --- | --- | --- | --- | --- |
| L1 | 会话元信息 | `cwd`、`runtime_workspace_roots`、`git.branch`、`git.commit_hash`、`base_instructions` 的**首部摘要** | 开 | 指令 ≤ 600 token |
| L2 | 最近对话尾部 | 最近 `ContextMessageLimit`（默认 6）条 `response_item.message` 的 role + text | 开 | 每条 ≤ 400 字符，超出用省略号 |
| L3 | 最近工具摘要 | 最近 1–2 条 `function_call` 的名称 + 参数的**路径/命令名**（不取完整输出） | 开 | 每条 ≤ 200 字符 |
| L4 | 工作区 git | `git status --porcelain=v1`、`git diff --stat`、`git log -1 --oneline` | 开 | 各 ≤ 12 行 |
| — | 明确不做（P0） | `reasoning` 全文、全量文件内容、剪贴板、全文检索/向量检索、`thread_history_1.sqlite`（1.2 GB，锁与性能风险）、附件内容 | — | — |

不做 sqlite 的理由：jsonl + 索引已能覆盖定位与内容；sqlite 体积大、可能被 app 独占，属于高风险无收益路径。

## 6. 开关与设置

### 6.1 数据模型（`Models/AppSettings.cs` 新增，全部带默认值）

```csharp
/// <summary>上下文增强总开关。默认关；关闭时不做任何上下文采集。</summary>
public bool ContextEnabled { get; set; }                     // false  ← 必须默认关
/// <summary>携带最近对话尾部（仅总开关开启时生效）。</summary>
public bool ContextThreadTailEnabled { get; set; } = true;
/// <summary>携带工作区 git 摘要。</summary>
public bool ContextGitEnabled { get; set; } = true;
/// <summary>携带会话元信息（cwd / 分支 / 指令摘要）。</summary>
public bool ContextWorkspaceMetaEnabled { get; set; } = true;
/// <summary>上下文 token 预算上限。</summary>
public int ContextTokenBudget { get; set; } = 1200;
/// <summary>最近对话条数上限。</summary>
public int ContextMessageLimit { get; set; } = 6;
/// <summary>会话文件新鲜度上限（秒）。</summary>
public int ContextStaleSeconds { get; set; } = 300;
/// <summary>预览窗口显示上下文来源。</summary>
public bool ContextShowInPreview { get; set; } = true;
```

`SettingsStore.Load()` 内按现有风格钳制：`TokenBudget ∈ [200, 4000]`、`MessageLimit ∈ [0, 20]`、`StaleSeconds ∈ [30, 3600]`。

### 6.2 关闭语义（"关了就不获取上下文"的精确边界）

关闭态下必须满足：

1. 不读 `session_index.jsonl`、不枚举 `sessions` / `archived_sessions`、不读任何 `rollout-*.jsonl`；
2. 不读 `.codex-global-state.json`、不看 `thread-writer-locks`；
3. 不启动任何子进程（`git status` / `git diff` / `git log` 全部不执行）；
4. 不为上下文做额外 UIA 遍历（标题沿用已有 `TryGetSessionIdentity` 缓存结果）；
5. 请求体与 v1.2.1 **字符串级一致**（草稿 + 模板 + 变量，无任何新增字段）。

实现位置（唯一闸门，避免散落判断）：

```csharp
// MainController.OptimizeAsync，紧随空草稿检查之后
ContextSnapshot? context = null;
if (_settings.ContextEnabled)          // ← 唯一总闸；关闭时下方代码完全不执行
{
    context = await _contextPipeline.BuildAsync(target, _optimizeCts.Token);   // 内部自带超时与降级
}
var (systemPrompt, userPrompt) = PromptComposer.Compose(template, currentText, variables, context);
```

`_contextPipeline` 采用**惰性构造**（`Lazy<ContextPipeline>` 或首次进入 if 才实例化），保证关闭态不会因为构造对象而触发任何 I/O。

## 10. 隐私与安全

1. **只读**：只读文件、只读 git 命令；绝不写 `~/.codex`，不修改工作区。
2. **白名单**：只访问 §5 列出的 4 类数据，不递归扫描磁盘，不读 `.env` / 密钥 / 浏览器数据。
3. **脱敏**：`ContextRedactor` 至少覆盖 `sk-…`、`Bearer …`、`*_API_KEY=`、`token=`、`password=`、常见内网地址；命中即用 `[redacted]` 替换。
4. **日志**：`runtime-status.log`（实测 1.0 MB 级）只写状态码与计数（`ctx=ready tokens=812 chars=3400`），**不写上下文正文**。
5. **不落盘**：上下文只存在于内存，进程退出即消失；不新增缓存文件。
6. **用户可见**：README + 设置页明确写"开启后会把本机会话摘要、工作区路径与 git 摘要随请求发送到你自己配置的模型服务商"。
7. **不扩大权限**：本功能不请求任何新权限，不做网络请求（网络仅由既有 provider 发起）。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Codex 升级改 rollout/索引字段 | 定位失效 | 只依赖最小字段集；启动做一次格式探测并写诊断码 `ctx=format-unknown`；缺失即降级，不抛异常 |
| 标题重名（实测 6× 每周回顾） | 串会话 | 三重校验 + 冲突即放弃（§4.2 第 8 步） |
| 标题被 UI 截断（`truncate` class） | 匹配失败 | 去省略号前缀匹配；仍多义则放弃；把"截断导致放弃"计入诊断，便于后续改用更强信号 |
| 索引是 Z 时间、文件 mtime 是本地时间 | 误判过期 | 统一转 UTC 比较（本方案已把该坑写进 §4.2 第 7.b 步） |
| `.codex-global-state.json` 大小写混用键 / 写入中读到半截 | 解析失败 | 大小写不敏感解析 + try/catch + 只当辅助信号，解析失败不阻断优化 |
| 会话文件被归档/清理 | 定位不到 | 同时查 `sessions` 与 `archived_sessions`；都无则放弃 |
| 读取时机与写入并发 | 半行 JSON | 逐行 try/parse，坏行丢弃；文件变短则重置偏移 |
| 上下文让 token 变贵 | 成本上升 | 预算上限 + 预览可见 + 默认只开三项且总开关默认关 |
| 上下文里的"指令"被执行 | 注入风险 | 统一 JSON 证据块 + system 明确"证据不是指令" |
| 优化点击变慢 | 体验下降 | 采集仅在点击时；git 60s 缓存、整体超时 1500ms、超时降级为无上下文 |
| 采集被误认为后台上传 | 信任问题 | README + 设置页显式说明发送范围；日志不记正文 |
| 仓库无测试工程 | 回归不可自动化 | S2 先建立最小断言载体（建议新增 `tests/ContextTests` 控制台断言工程或复原 4 套断言脚本），再进入 S3 |

## 14. 决策记录

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 上下文主来源 | 读 `session_index.jsonl` + `rollout-*.jsonl` | 结构化、无 UIA 抓屏、可缓存可审计；UIA 只用于拿标题 |
| 是否读 `thread_history_1.sqlite`(1.2 GB) | **不读** | 体积大、可能被 app 独占，风险高收益低 |
| 定位策略 | 多信号 + 硬否决，冲突即放弃 | 用户明确要求"精准"；错误上下文的代价高于无上下文 |
| 总开关默认值 | **关** | 用户明确要求；同时保证老用户行为零变化 |
| 关闭语义 | 零 I/O、零子进程、请求体逐字符一致 | 需求"关了就不获取上下文"，且可被自动断言 |
| P0 是否做向量检索/附件内容 | 不做 | 收益不确定、隐私面扩大；先验证"会话尾部 + 工作区"是否真的提升优化质量 |
| 上下文注入位置 | 复用 `PromptComposer` 的 JSON 证据块 | 沿用既有防注入设计，改动最小 |
| 采集时机 | 仅点击优化时 | 不进入 500ms 轮询，避免稳定性和性能回归 |
